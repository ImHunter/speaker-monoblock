# AGENTS.md

Проект: колонка-моноблок ([README.md](README.md)). Документы на русском, ключи YAML и ID на латинице.

## Куда идти
| Задача | Файл |
|---|---|
| Любое число (размер, координата, момент, частота) | `params.yaml` |
| Компонент, ограничения, цена, статус | `components.yaml` |

| Нерешённое | `docs/open-questions.md` |

Загружай только нужные файлы, а не весь репозиторий.

## Правила
1. **Числа живут в `params.yaml`.** Меняешь число — меняй там, затем `make sync`. Новое число в тексте записывай с маркером `<!--p:путь.к.параметру-->` сразу после числа, если оно нужно более чем в одном месте.
2. **Не выдумывай данные.** Нет значения в `params.yaml` или `components.yaml` — не подставляй из памяти: добавь вопрос `OQ-NNN` в `docs/open-questions.md` и спроси человека.
3. **Ссылки по ID:** компоненты `CMP-…` (из `components.yaml`), приёмы `T-NNN` (заголовки `## T-NNN` в `techniques.md`), вопросы `OQ-NNN`. Не переименовывай ID без замены всех ссылок.
4. **Безопасность.** Сетевая часть — только по `docs/power-input.md`, раздел «Запреты» не нарушать. PE всегда независимым транзитом на FG. Работы под напряжением не предлагать.
5. **Решения.** Изменение принятого решения (выбор компонента, топологии, частоты раздела) — запись в `docs/project.md` («Принятые решения») и в `CHANGELOG.md`.
6. **Перед коммитом** `make validate`. Ошибки не игнорировать.
7. **Коммиты:** `<раздел>: что сделано`, например `enclosure: уточнить размеры боковин`.
8. Исходный монолит `archive/` — только для справки; не править.
9. Тяжёлые файлы (PDF, чертежи, `.dspproj`) — в `datasheets/` и `dsp/sigmastudio/` (Git LFS); имя PDF = ID компонента.

## Статусы
Все разделы `draft`, пока человек не подтвердил. Не помечай что-то проверенным без измерения или подтверждения.
