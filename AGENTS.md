# AGENTS.md — инструкция для агентов

Проект: колонка-моноблок (см. [README.md](README.md)). Язык документов — русский, идентификаторы и ключи YAML — латиница.

## Карта репозитория

| Задача | Куда идти |
|---|---|
| Узнать любое число (размер, координата, момент, частота) | `params/*.yaml`, `params/panels/*.yaml` |
| Узнать свойства компонента, ограничения, поставщика | `components/**/<id>.yaml` |
| Понять, почему выбрано решение | `docs/decisions/ADR-*.md` |
| Собрать/проверить конкретный узел | `modules/<имя>/` |
| Выполнить приём монтажа (обжим, клипсы, слабина) | `techniques/T-*.md` |
| Порядок сборки целиком | `assembly/sequence.yaml` → `assembly/stage-*.md` |
| Первый запуск, приёмка | `commissioning/` |
| Термины | `docs/glossary.md`, оси и единицы — `docs/conventions.md` |
| Что не решено | `docs/open-questions.md` |

Роли: `agents/builder.md`, `agents/procurement.md`, `agents/reviewer.md`, `agents/dsp-engineer.md`. Если задача подходит под роль — прочитай её файл.

## Правила

1. **Один факт — одно место.** Не копируй числа в прозу. Пиши «см. `params/panels/front.yaml`, `woofer`» или подставляй значение со ссылкой. Если число нужно в тексте, укажи источник в скобках.
2. **ID ссылок стабильны:** компоненты `CMP-…`, приёмы `T-NNN`, решения `ADR-NNN`, шаги `STEP-<МОДУЛЬ>-NN`, тесты `TEST-<МОДУЛЬ>-NN`, вопросы `OQ-NNN`. Не переименовывай ID без замены всех ссылок (`make validate` их проверяет).
3. **Статусы модулей** лежат в `project.yaml`: `draft | reviewed | frozen | built | tested`. Модуль `frozen` или выше не меняй без нового ADR и согласия человека.
4. **Не выдумывай данные.** Если параметра нет в `params/` или паспорте, не подставляй из памяти: добавь запись в `docs/open-questions.md` и спроси.
5. **Безопасность.** Сетевая часть (220–250 В) — модуль `power-input`. Не предлагай изменения, нарушающие `modules/power-input/prohibitions.md`, и всегда сохраняй независимый транзит PE на FG блока питания.
6. **Коммиты:** `<модуль>: <что сделано>` (например `power-input: уточнить момент затяжки`). Изменение решения — отдельный ADR. Изменение числа в `params/` — в сообщении укажи, какие документы затронуты.
7. **Перед коммитом:** `make validate`. Ошибки валидации не игнорировать.
8. **Файлы в `components/datasheets/`** — PDF/чертежи через Git LFS, имя = ID компонента. Не читай их целиком, если хватает паспорта.
9. **Исходник `archive/проект-колонки-v8.0.md`** — только для справки. Источник истины — файлы репозитория.
